# DJ WOOD — المرحلة 56: الخادم المركزي وواجهة API

هذه حزمة خادم للمرحلة التالية من المتجر. تستخدم Node.js 22 LTS وExpress 5 وPostgreSQL. لا تحتوي على مفاتيح أو كلمات مرور فعلية.

## ما الذي توفره؟

- API للصحة والكتالوج العام والمنتجات والعملاء والطلبات.
- كتالوج عام لا يعرض أسعار الشراء أو سجل الأسعار الداخلي.
- نقطة استقبال عامة `POST /api/v1/orders/submit` تقبل الدفع عند الاستلام فقط في هذه المرحلة.
- إعادة حساب سعر الطلب على الخادم من سعر المنتج المسجل، وعدم الوثوق بإجمالي العميل أو برسوم التوصيل التي يرسلها المتصفح؛ رسوم التوصيل تحددها متغيرات الخادم `DELIVERY_FEE_DZD` و`FREE_DELIVERY_THRESHOLD_DZD`.
- حجز الكمية في PostgreSQL ضمن معاملة واحدة مع قفل صفوف المنتجات؛ يمنع قبول طلبين على آخر كمية متاحة.
- مفاتيح idempotency ورمز خاص عشوائي لكل طلب لتأمين إعادة الإرسال ومنع كشف بيانات العميل عند تخمين مرجع الطلب.
- لوحة إدارة مركزية على `/admin.html` لتسجيل دخول المدير، واستعراض الطلبات والمخزون، وتغيير حالات الطلبات مع تحديث المخزون.
- لوحة API إدارية محمية برمز JWT، مع تسجيل دخول وتحقق من إصدار السجل (If-Match) لتعارض التعديلات.
- إلغاء الطلب يحرر الحجز، والتسليم يخصم من المخزون ويستهلك الحجز.
- عدم السماح بحذف الطلبات نهائيًا؛ استخدم انتقال الإلغاء حتى يبقى سجل المخزون.

## التشغيل محليًا

1. ثبّت Node.js 22.9 أو أحدث وPostgreSQL 14 أو أحدث.
2. أنشئ قاعدة بيانات ومستخدمًا خاصًا بالتطبيق.
3. انسخ `.env.example` إلى `.env` واضبط `DATABASE_URL`.
4. أنشئ كلمة مرور إدارية قوية ثم ولّد تجزئتها:

```bash
npm install
npm run admin:hash -- "ضع-كلمة-مرور-قوية-لا-تقل-عن-12-حرفًا"
```

5. ضع القيمة المطبوعة في `ADMIN_PASSWORD_HASH`، وأنشئ `JWT_SECRET` عشوائيًا بطول 32 بايت على الأقل، مثل:

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

6. صدّر نسخة احتياطية من المتجر وضعها بجانب المشروع، ثم استورد المنتجات إلى قاعدة البيانات:

```bash
npm run import:products -- ./backup.json
```

7. اضبط `DELIVERY_FEE_DZD` و`FREE_DELIVERY_THRESHOLD_DZD` حسب سياسة التوصيل الفعلية، ثم شغّل `npm start`.
8. افحص `http://localhost:8787/api/v1/health` وافتح المتجر من `http://localhost:8787/` ولوحة الإدارة من `http://localhost:8787/admin.html`.

## ربط ملف المتجر

- عند استضافة HTML وAPI على النطاق نفسه، يستخدم ملف المتجر تلقائيًا `/api/v1` على نفس النطاق.
- إذا كان HTML في نطاق منفصل، اضبط `ALLOWED_ORIGINS` في الخادم، ثم عيّن عنوان API في المتصفح باستخدام:

```js
DJWoodAPI.setBaseUrl('https://YOUR-API-HOST/api/v1')
```

- الكتالوج العام متاح من `GET /api/v1/catalog` ولا يعرض أسعار الشراء.
- استقبال الطلبات من العملاء يتم عبر `POST /api/v1/orders/submit`.
- العمليات الإدارية تحتاج `Authorization: Bearer <token>` بعد `POST /api/v1/auth/login`.

## النشر على Render

ملف `render.yaml` يعرّف خدمة Docker وقاعدة PostgreSQL. راجع كل متغير بيئة قبل النشر، خصوصًا `ADMIN_PASSWORD_HASH` و`ALLOWED_ORIGINS`. لا تضع كلمة المرور أو JWT secret داخل ملف HTML أو المستودع.

## أمثلة API للإدارة

تسجيل الدخول:

```bash
curl -X POST http://localhost:8787/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"YOUR_PASSWORD"}'
```

استخدم `token` الناتج في `Authorization: Bearer TOKEN` عند استعراض الطلبات أو إدارة المنتجات. لا ترسل الرمز إلى العملاء ولا تضعه داخل HTML.

## حدود هذه المرحلة

- لم يتم نشر الخدمة على حساب استضافة فعلي بعد؛ يلزم ربط حساب Render والموافقة على إنشاء موارد الاستضافة وقاعدة البيانات. قد تترتب رسوم على خطة الخادم وقاعدة البيانات؛ راجع الأسعار قبل تأكيد النشر.
- لوحة الإدارة المركزية الحالية تعرض الطلبات والمخزون وتسمح بتغيير حالات الطلبات. إدارة المنتجات الكاملة من الواجهة (إضافة/تعديل) وربط لوحة الإدارة القديمة بقاعدة البيانات سيُستكمل في مرحلة لاحقة؛ يمكن استيراد المنتجات من نسخة احتياطية باستخدام أداة الاستيراد.
- لا توجد بوابة دفع إلكتروني مرتبطة. هذه المرحلة تقبل COD فقط، ولا تسجل الدفع الإلكتروني.
- محددات محاولات تسجيل الدخول والطلبات العامة في هذه النسخة تحفظ العدادات في ذاكرة العملية؛ عند تشغيل عدة نسخ خادم، انقلها إلى مخزن مركزي مثل Redis أو طبقة حماية الاستضافة.
- عند استضافة المتجر على HTTP(S)، لا يعرض التطبيق المنتجات المحلية التجريبية إذا تعذر الوصول إلى الخادم أو كان الكتالوج المركزي فارغًا، ولا يعتمد الطلب إذا كان الخادم غير متاح. هذا يمنع ظهور منتجات تجريبية على أنها مخزون حقيقي. يلزم استيراد منتجات المتجر إلى قاعدة البيانات قبل عرض الكتالوج المركزي. يمكن استخدام نسخة احتياطية DJ WOOD كاملة؛ يستخرج البرنامج منها `DJ_WOOD_PRODUCTS_V1`، أو ملف JSON يحتوي على مصفوفة المنتجات أو الخاصية `products`. شغّل `npm run import:products -- ./backup.json` بعد ضبط `.env`. إذا كان الكتالوج المركزي فارغًا أو الخادم غير متاح، لا تُحذف بيانات المتصفح المحلية لكنها تُخفى مؤقتًا في نسخة HTTP(S) حتى لا تُعرض منتجات تجريبية على أنها مخزون حقيقي.
- حدد `ALLOWED_ORIGINS` للنطاق الفعلي، واستخدم HTTPS، واحتفظ بنسخ احتياطية لقاعدة البيانات.

## الاختبارات

شغّل `npm test` لاختبارات منطق الكتالوج، وإخفاء بيانات الشراء، وحساب وحدات m³/m²/القطعة، والتحقق من الكميات وحالات الطلب. اختبار اتصال PostgreSQL الحقيقي يتطلب قاعدة بيانات تشغيلية.
